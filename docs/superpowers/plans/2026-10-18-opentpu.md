# openTPU Python Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package the full openTPU Python distribution for EmberBSD AArch64 and run selected upstream CPU tests on the local host.

**Architecture:** Add a pure-Python pkgsrc wheel recipe under `pkgsrc/local-ai`. Cross-build it with the current GCC16 pkgsrc profile and the target sysroot. Build a host wheel from the same pinned source, install it in a temporary virtual environment, and run the upstream ISA, compiler, and kernel suites.

**Tech Stack:** pkgsrc-2026Q3, Python `wheel.mk`, Python 3.15 target, Python 3.12 host, GCC 16.2.0 cross profile, pytest, NumPy.

**Spec:** `docs/superpowers/specs/2026-10-18-opentpu-design.md`

## Global Constraints

- Source revision: `730ca28feb77b5598090e97ab209f302f0c56eec` (`v0.5`).
- Source archive SHA512: `c1d06fcc1831c36cdf20ccbc6066e0f14d41b5dacddfaa1a53023b4e740911de39b13b75adb6dce9876216e65d929b003891f56b80e2df31902ea60daad9f2b4`.
- Preserve Python project version `0.1.0`, Python floor `>=3.10`, Apache-2.0 license, and NumPy runtime dependency.
- Package all `opentpu` modules, four console entry points, and declared package data.
- Use GCC 16.2.0 and the existing AArch64 cross pkgsrc profile.
- Complete the GCC16 AArch64 Fortran and pkgsrc cross prerequisite in `2026-10-18-gcc16-aarch64-fortran.md` before building NumPy with BLAS.
- Do not claim FPGA, XDMA, Vivado, RTL, EmberBSD runtime, or model inference acceptance.
- Do not add a project-owned Python helper or add pytest to the runtime package.

## Review Focus

- Source tag and archive identity can diverge; `bmake checksum` must verify the pinned archive.
- The Git tag is `v0.5` while wheel metadata is `0.1.0`; pkgsrc metadata and installed wheel metadata must retain `0.1.0`.
- An incomplete PLIST can omit modules, package data, license files, or scripts; compare the final package payload with the generated PLIST.
- A cross-installed script can retain the host interpreter; inspect all staged script shebangs for the target Python path.
- A missing NumPy dependency or hardware claim misstates package behavior; inspect pkgsrc dependency metadata and the published README text.
