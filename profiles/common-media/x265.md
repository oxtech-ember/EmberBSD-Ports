# x265 4.2 cross build and CM5 check

The common media profile supplies the complete x265 4.2 HEVC encoder, CLI,
shared/static libraries, headers and pkg-config metadata. The
[upstream download inventory](https://api.bitbucket.org/2.0/repositories/multicoreware/x265_git/downloads)
listed 4.2, published 2026-04-19, as the newest release on 2026-10-12.
The original archive and SHA256 are pinned in [sources.tsv](sources.tsv).

The `4.2nb2` recipe preserves all nine pkgsrc patches, RCS identifiers and
licences. It stops setting `CMAKE_SYSTEM`, a CMake-derived value. That setting
prevented target initialization: the Mac cross build selected Darwin and
passed `-arch arm64` to the AArch64 GCC driver. The recipe still supplies the
target system name, version and processor. No compiler check is bypassed.
The one-line recipe correction and checks are AI-assisted EmberBSD work,
not an accepted upstream contribution.

## Reproduce

Prepare the normal [export](README.md), then
cross-build and install the complete `multimedia/x265` package against the
verified EmberBSD sysroot. Check the real recipe and CMake selection:

```sh
BMAKE=/path/to/bmake TEST_CMAKE=/path/to/cmake \
  ruby profiles/common-media/tests/x265-cross.rb \
  PREPARED_PKGSRC CROSS_MAKECONF NEW_WORK
ruby profiles/common-media/tests/x265-fixtures.rb prepare NEW_FIXTURES
cp profiles/common-media/tests/x265-runtime.sh NEW_FIXTURES/
```

Transfer the verified fixtures and package to the target and run:

```sh
sh NEW_FIXTURES/x265-runtime.sh NEW_FIXTURES NEW_RESULTS
```

Copy results back and decode with an independent installed FFmpeg:

```sh
FFMPEG=/path/to/ffmpeg ruby profiles/common-media/tests/x265-fixtures.rb \
  verify COPIED_RESULTS NEW_FIXTURES
```

The test uses four changing 64×64 YUV420 frames, lossless encoding, one worker
pool and one frame thread. Both NEON and scalar modes must reconstruct the
original bytes. Independent decoding must reproduce all 24,576 source bytes.
The target log must identify NEON and the scalar control respectively.
No display, camera or video hardware decoder is accessed.

## Acceptance, 2026-10-12

GCC 16.2.0 on macOS/AArch64 built the full package. Standard file, interpreter,
permission, PIE/RELRO, RPATH and work-directory checks passed. The real recipe
initialized cross compilation; restoring the original derived variable in
the CMake control left cross compilation uninitialized.

CM5 Rev 1.0, BCM2712 D0, 4 GiB, Waveshare CM5-NANO-B passed both encoding modes.
Host FFmpeg 9.0.2 decoded both HEVC streams to exactly the original pixels.
All seven installed package files matched the sysroot by SHA256;
`pkg_admin check` passed. The existing fan kernel was unchanged, source
`ab6f88f04ca73c6958adb39d0e1c717f629e7901`, SHA256
`c8600af1c6a31404fe6b3a3995196a910efda594c708194369925adb54ff1886`.
The boot timestamp did not change during the test.

All 12 media archives and patch digests passed; patches applied without fuzz.
Both export modes rejected an absent x265 recipe or an altered source pin.
Cppcheck 2.22 analyzed 71 actual C/C++ compilation units. Its result is **not
clean**: inherited initialization, pointer, bounds and shift diagnostics remain.
Some diagnostics involve implementation-specific signed shifts and pthread
initialization; this bounded port does not claim their full triage or memory
safety. Valgrind was unavailable.

Upstream selects baseline NEON on this platform; optional DotProd, I8MM and
SVE runtime dispatch are not established. The nondefault 10-bit build was
not tested. This short HEVC check does not prove full FFmpeg playback,
video hardware acceleration, long-running encoding or a Plasma session.
