# A733 compute image generator

Builds a CPU-generated compute submission for the PowerVR BXM GPU
(BVNC `36.56.104.183`) from Mesa 26.2.4 producer functions. The image is
intended for the EmberBSD diagnostic ladder (stages 18–21) on Orange Pi Zero 3W.
The version-3 packet from Ports `5134eae` passed all 21 stages on 2026-10-13
with OS `7cde8f93b68`. The guarded shader wrote `0x13579bdf`, and the
client queue, timeline, and fresh firmware checks agreed. This acceptance
covers one native diagnostic dispatch, not Vulkan or rendering.
See the [OS compute check](https://github.com/oxtech-ember/EmberBSD/blob/main/ember/boot/a733-gpu-fwcompute.md).

## Layout

- `generate.c` — bounded generator: packs the four USC precompiled
  shaders, PDS programs, context-switch state, and the CDM-2 stream.
  This bounded diagnostic uses a low USC execution alias at `0x2000`.
  Keep the kernel aliases in `sun60i_a733_gpu_fwheap.c` consistent.
  These aliases are not the general userspace heap layout.
- `extract-usclib.rb` — extracts the precompiled shaders
  (`probe/store/load/idfwdf.precomp`) from the Mesa `pco_uscgen_programs`
  table after checked shader generation. It requires the compiler receipt.
- `build.rb` — compiles the generator against the Mesa host objects.
- `run.rb` — acceptance runner: verifies input hashes, runs the
  generator, checks the manifest, and refuses reuse of old outputs.

## Inputs

`probe.precomp`, `store.precomp`, `load.precomp`, `idfwdf.precomp` from
the Mesa host-tools build (`host-tools/README.md` describes that build).
Create their input manifest with the checked extractor:

```sh
ruby extract-usclib.rb "$PROGRAM_OUTPUT/programs.c" \
    "$PROGRAM_OUTPUT/receipt.json" "$NEW_SHADER_DIR" "$INPUTS_JSON"
```

The `probe` is `cs_probe_store`, with an explicit zero-instance guard.
The query-availability shader is not a diagnostic store probe.
The runner checks SHA256, the compiler receipt, the shared ABI header,
and exact equality with every selected compiler-generated byte array.
IDFWDF uses ten dwords: texture 0–3, sampler 4–7, and address 8–9.
The original common compiler input used address slots 5 and 6.
Its binaries cannot be combined with the fixed host layout.

## Outputs

`general.bin`, `pds.bin`, `usc.bin`, `static-state.bin`, `border.bin`, and `command.bin` plus
`manifest.json` with hashes, resource VAs, and sizes. The EmberBSD-side
packer (`ember/tools/a733-gpu-compute-firmware.c`) wraps them into the
version-3 firmware file `a733-compute.bin` with the ten-resource table
and the payload digest; install it under `/libdata/firmware/powervr/`
on the board.

The command uses unchanged `pvr_submit_info_stream_init` and flag producers.
It contains a 44-byte KMD stream and four bytes of DRM compute flags.
Resume PDS allocation fields come from the generated load program and context.
The context-state address binds to the writable resume resource.
The full border table has 64 entries. Mesa fills the six builtin colors.
The CPU adapter keeps unallocated custom entries zeroed.
Its read-only GPU address is `0x8000010000`.
The adapter has no DRM allocation, mapping, or submission path.
Each output records its actual size. Shader sizes must not be inherited from an older build.
This format requires the OS version-3 packer and parser.

## Validation scope

The generator produces compiler bytes on the CPU only. Hardware
execution is the kernel ladder's domain; no GPU, DMA, or firmware
interaction happens here. Shader and host ABI parser contracts pass with the
original wrong-layout input as a negative control. Fresh code generation and
physical execution must be recorded separately for each artifact.
